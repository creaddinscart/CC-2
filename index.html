01 / Capabilities

Everything in the box

Eight things the Terminal Edition does without a single server you have to rent or trust.

End-to-end encryption

PBKDF2-SHA256 derives the key locally. AES-256-GCM with a zero-dependency HMAC-CTR fallback.

Room = local server

Creating a room starts a temporary server on your own machine. Close it and it is gone.

Probe before password

Guests verify a real CC-2.0 room exists before any password is requested.

Mouse-driven terminal

Buttons, fields, transport list, file picker and member list are all clickable.

Typing indicators

Every client shows who is typing, carried inside an encrypted payload.

Encrypted file transfer

Files are chunked, encrypted and reassembled into ~/Downloads/CC-2.0/.

Live member cap

The host changes capacity inside the room, kicks members or closes the room.

Transport ranking

IPv6 global, public IPv4, VPN / Radmin VPN and LAN addresses are auto-detected.

02 / Architecture

What the server can and cannot see

The room server is a dumb switch. It moves opaque ciphertext and verifies a separate authentication token - it never holds the message key.

Host machine

Your terminal

curses client, local key derivation, file picker.

  • Password never leaves the client
  • Key derived from password + salt
  • Plaintext stays in RAM
→join
Temporary room server

Bound to your chosen port

Started by Create Room, stopped when the room closes.

  • Sees ciphertext, usernames, timestamps
  • Stores an independent auth verifier
  • Cannot recover the message key
  • Cannot read text or files
→ciphertext
Guest machines

Peer terminals

Connect by IP + port, probe, then unlock with the password.

  • IPv6 preferred
  • Caps negotiated across members
  • History replayed as ciphertext
Trust model: the password is the only key source and must be shared out of band. If any member lacks the optional cryptography package, the whole room transparently downgrades to the built-in HMAC-CTR cipher so everyone can still read every message.

03 / Get started

From zero to an encrypted room

Python 3.9 or newer is all you need. Optional packages enable AES-256-GCM and, on Windows, the mouse-driven terminal UI.

terminal
$ unzip CC-2.0.zip && cd CC-2.0
$ chmod +x CC-2.0.command
$ ./CC-2.0.command
terminal
$ unzip CC-2.0.zip && cd CC-2.0
$ chmod +x CC-2.0.sh
$ ./CC-2.0.sh
command prompt
> python -m pip install windows-curses
> CC-2.0.bat
terminal
$ python3 -m pip install -r requirements.txt
$ python3 launch.py
$ python3 launch.py --cli
$ python3 launch.py --server
$ python3 launch.py --test

  1. Pick a mode and choose a username

    Launch the app and select 1 Terminal UI. On the first run you create a username; it is saved in ~/.cc2/config.json and reused next time.

    1 Terminal UI2 Headless server3 Self-tests

  2. Host: create a room

    Click Create Room and fill in room name, port, communication IP, password and maximum members. The transport list is auto-detected and ranked; pick an address or type a custom one (IPv6 global is preferred). Creating the room starts the temporary server and drops you straight into chat.

    Name night-shiftPort 7777IP auto / customPassword shared out of bandCap 8

  3. Guest: check the room, then unlock it

    Enter the host's IP + port and click Check Room. A valid CC-2.0 room replies with its name, host, member count and capacity. Only after that does the client ask for the password. Wrong password, duplicate username and full room are all rejected.

  4. Chat, type and send files

    Type in the input line and press ENTER. Peers see "name is typing..." while you type. Click File to open the built-in picker; files are encrypted, chunked and reassembled into ~/Downloads/CC-2.0/. All mouse targets in the terminal are clickable, and TAB / arrows / ENTER / ESC work as keyboard alternatives.

    TAB next fieldENTER confirmESC backMouse buttons, lists, files, members

  5. Host: tune the room live

    Inside the room the host can raise or lower the member cap at any time based on the machine's load, kick a member, or close the room. Closing stops the temporary server immediately.

04 / Networking

How peers find each other

Addresses are discovered locally, ranked, and shown in the creation form. Radmin VPN ranges (26.0.0.0/8) are recognised automatically.

01IPv6 globalpreferredUsed first when a global IPv6 address exists. Best for direct peer-to-peer reachability without NAT.
02Public IPv4 / WANfallbackChosen when no global IPv6 is available. Usually needs port forwarding on the router and an open firewall port.
03VPN / Radmin VPNvirtual lanAll peers join the same virtual network, then use the VPN-assigned IP. Works across the internet without exposing a public port.
04LANlocal networkSame Wi-Fi or Ethernet. Fastest and simplest for a room that only needs to exist in one building.
05Loopbacklocal testing127.0.0.1 / ::1 for a single-machine test. Host and guest run in two terminals on the same computer.
If a peer cannot connect: confirm the host's firewall allows the chosen TCP port, that the port is forwarded for public IPv4, that all peers are on the same VPN, and that the advertised IP is the one peers can actually route to. Use python3 cc2_server.py --list-addresses to inspect what the host sees.

Troubleshooting

  • Terminal looks cramped - enlarge the window; the layout adapts from 80 columns upward.
  • Mouse does nothing - enable X10 mouse reporting in your terminal, or use TAB / arrows / ENTER.
  • Windows curses error - install windows-curses from requirements.txt.
  • Peer times out - check firewall, port forwarding, VPN membership and the advertised IP.
  • Old messages unreadable - a new password produces a new key; cached history is silently skipped.
  • No AES-GCM - the room falls back to HMAC-CTR automatically; install cryptography for AES-256-GCM.

Security notes

  • The room password is never transmitted; the server stores only a separate auth verifier.
  • Usernames, member counts and timestamps are visible to the server in plaintext.
  • There is no forward secrecy and no identity verification beyond the shared password.
  • Share the password over a different channel than the room address.
  • Closing the room stops the server and drops all in-memory state.
